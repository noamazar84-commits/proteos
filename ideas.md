# Proteus design brief

## Direction
Preserve the existing Proteus product identity and visual language; this is an extension of the current consumer app, not a rebrand. The admin CRM should feel like the same product while prioritizing legibility and fast scanning.

## Design dimensions
- **Movement:** dark, precise, modern product UI with restrained sci-fi energy.
- **Principles:** clear hierarchy, high information density only where useful, accessible contrast, and no fake customer data in a live management screen.
- **Color:** deep navy surfaces, cool white text, muted slate labels, and the established electric-volt blue for primary actions and focus states; status colors remain semantic.
- **Layout:** centered responsive container; KPI strip above a wide, horizontally scrollable customer table; filters and search stay compact.
- **Signature elements:** subtle grid texture, translucent panels, rounded pills for subscription states, and the existing Proteus logo.
- **Interaction:** immediate search/filter feedback, explicit loading/empty/error states, and no account or subscription action that implies success before the server confirms it.
- **Animation:** reuse existing soft rise/glow motion sparingly; respect reduced-motion preferences.
- **Typography:** existing Sora display headings and Inter body/interface text.
- **Brand voice:** calm, direct, clinically informed, and supportive without making billing or health promises.
- **Wordmark/logo:** retain the existing Proteus logo and header treatment.
- **Signature color:** the existing electric blue/volt accent against deep navy.
